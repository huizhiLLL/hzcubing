# 积分项目实施设计

2026-11-26 · 方案已确认

## 项目分类与录入

「积分」是继「官方」「趣味」「整活」之后的第四个公开分类。管理员在项目管理页新增项目时，可选「整活」或「积分」，默认「整活」。编辑时分类只读，可以修改名称、描述和启用状态。补录使用的「历史」分类保留现有用途。

`events.category = 'score'` 决定项目采用积分规则，其余分类沿用当前计时逻辑。积分项目的一条成绩只录入一个数字，表单字段和表格列名都叫「成绩」。例如，输入 `120.5` 后，个人主页、排行榜、群纪录和群通知都显示 `120.5`。成绩文本统一为数字本身，分类名统一为「积分」。

## 数据与接口

- 新增 D1 迁移 `migrations/0004_score_events.sql`，扩展 `events.category` 的 `CHECK`，在 `records` 增加可空的 `score REAL` 和按 `(event, score DESC)` 建立的非空部分索引。原项目分类、项目编码、行顺序、成绩原值和关联关系逐项保留。
- `POST /api/events` 和 `POST /api/bot/events` 接收可选的 `category`，允许 `meme` 或 `score`，省略时用 `meme`。沿用各入口现有权限。`PATCH /api/events/:code` 可编辑这两类项目的现有可编辑字段。请求若传入不同的分类，返回 `400`。
- 网页与 QQ 录入复用 `worker/records.ts` 的校验。积分提交使用 `{ "event": "项目编码", "score": 120.5 }`。`score` 接受有限的 JSON 数字或经去除首尾空格后形如 `120.5`、`0`、`-2.5` 的十进制字符串，绝对值上限为 `Number.MAX_SAFE_INTEGER`。字符串必须完整匹配 `[+-]?\d+(\.\d+)?`。空值、时间字符串、带单位字符串、`DNF` 和 `DNS` 返回 `400`。按数值保存和比较，保留小数，不做百分秒截断。
- 积分记录只写 `score`，时间成绩字段和 `solves` 置空。请求混用两类成绩字段时返回 `400`。积分成绩的 `PATCH` 省略 `score` 时保留原值。跨评判方式换项目返回 `400`，同评判方式换项目继续受现有的启用状态校验。停用项目保留查询和原项目内编辑，停止接受新成绩。

| 读取入口 | 积分响应约定 |
| --- | --- |
| 项目目录 `GET /api/events` | 返回 `category: "score"`，供前端选择页面和表单分支。 |
| 成绩详情、个人最佳和历史、排行榜 | 各成绩对象增加 `score`，积分记录的 `singleSeconds`、`averageSeconds` 为 `null`，计时记录的 `score` 为 `null`。 |
| 当前群纪录 `GET /api/records/best` | 项目条目增加 `score`，值为 `{ value, userNo, nickname, timestamp }` 或 `null`。积分项目的 `single`、`average` 为 `null`。 |
| 群纪录历程 `GET /api/records/gr` | 增加 `score` 数组，沿用成绩对象。积分项目的 `single`、`average` 为空数组。 |
| 网页及 QQ 录入响应 | 增加 `isScoreGR`、`previousScoreBest`。首个有效成绩算群纪录，计时项目分别返回 `false` 和 `null`。 |

积分榜沿用 `/api/records/leaderboard?event=…`。Worker 根据项目分类选用查询规则，积分项目收到旧链接中的 `type=average` 时仍返回积分榜。

## 排名与群纪录

- 每位选手取最高成绩。同一选手有多条最高成绩时，榜单按录入日期倒序、记录 ID 升序选一条代表记录。积分榜按成绩降序，同成绩并列，名次采用 `1、1、3`。并列列表按日期和 ID 稳定排序。先排名，再按昵称筛选。
- 个人最佳取 `MAX(score)`。群纪录历程按成绩日期、记录 ID 从前到后计算，首条有效成绩和之后严格更高的成绩进入历程。当前群纪录展示最早达到最高成绩的选手，同一日期按 ID 决定。删除或编辑成绩后，查询按当前数据重新计算。
- 网页录入继续在现有 D1 批处理中查询录入前最高成绩并写入新成绩。新成绩严格高于录入前最高成绩时触发现有群通知，首次录入也算刷新。通知示例为 `小明刷新示例项目群纪录，成绩 120.5`。QQ 录入返回同一套判定结果。

## 实施顺序

1. **D1 结构。** 在同一迁移中创建新项目表和引用它的新成绩表，先复制项目，再复制成绩，随后按子表、父表顺序删除旧表，重命名并重建索引。复制时显式保留项目 `rowid`，因为项目目录依靠它维持分类内顺序。用包含已有成绩的隔离数据库实际执行迁移，核对外键、完整字段、索引和行数。旧快照导入仍使用显式列清单，原快照的 `score` 由数据库默认留空。
2. **Worker。** 在 `worker/events.ts` 扩展分类校验、列表顺序及管理权限范围。在 `worker/records.ts` 实现积分写入与查询，在 `worker/users.ts` 扩展个人最佳、历史成绩与创建项目查询。`worker/index.ts` 的 QQ 路由继续调用共享函数。
3. **React。** 在 `src/next/api.ts` 注册分类和响应类型。`Events.tsx` 复用现有管理入口，页面标题改为「项目管理」，按「整活」「积分」分组。`Submit.tsx` 按所选项目显示一组对应字段，切换时清理前一套成绩输入，编辑时只提供相同评判方式的项目。`Board.tsx` 的积分榜与纪录历程使用单列「成绩」，隐藏单次／平均切换，积分榜只请求一份数据。`GroupRecords.tsx` 新增「积分」分类和对应的桌面表格、移动端列表。`Player.tsx` 的个人最佳拆成计时和积分两组。历史列表保留按分类筛选及原有分页，在当前页内用独立的积分区块展示「项目」「成绩」「日期」及现有管理操作。项目选择器沿用现有分组样式。
4. **文档与发布。** 实现后更新 `docs/api.md` 和 `docs/architecture.md`。生产工作流目前只发布 Worker，获准发布时先核对生产 D1 绑定、备份并单独应用迁移，再发布 Worker。积分写入启用前可回切旧 Worker 并保留新结构。生产产生积分记录后，采用修复版 Worker 处理发布问题，保留已写入成绩。

## 验收

- 在隔离环境用 `npx wrangler d1 migrations apply DB --local --config wrangler.jsonc` 验证空库和含历史数据的旧库，检查 `PRAGMA foreign_key_check`、迁移前后记录内容，以及已有计时项目的单次、平均和历史精度。
- 扩展 `scripts/smoke-worker.mjs`，用本地管理员和合成账号验证项目权限、分类创建和不可更改、网页 API 与 QQ API 的录入。四位选手按不同日期依次提交 `0`、`9.567`、`10`、`10`。核对榜单 `1、1、3、4`、个人最佳、首位达到 `10` 的纪录持有人、三条破纪录历程，以及追平时的 `isScoreGR: false`。覆盖错误格式、零值、修改、删除、停用与跨评判方式换项目。
- 运行 `npm run typecheck`、`npm test` 和 `npm run build`。在桌面和移动端宽度检查项目表单、榜单、个人主页和群纪录的布局边界，核对成绩文案只显示数字。
